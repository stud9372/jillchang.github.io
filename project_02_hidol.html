背景脈絡

我們要做的不是舊產品升級，而是一個從零開始的粉絲社群平台。

2023 年，團隊決定從 beanfun! 出發，打造全新的粉絲社群平台。初期會議裡最常出現的問題是：「這個功能原本也有，要不要帶過來？」討論很容易被舊產品記憶拉走，而不是回到新平台真正要解決的問題。

我先把討論拉回粉絲需求本身：不同類型 IP 的粉絲期待不同，有人重視即時消息，有人想被同溫層理解，也有人在意能否被 IP 看見。策略如果不先收斂，後面的功能就會變成舊模組拼裝。

粉絲不只是想要另一個追星 app，而是想要一個懂我熱愛的地方。
早期工作坊與 MVP 核心範圍梳理，協助團隊把不同 IP 的粉絲需求攤開討論。
探索整理

方向收斂後，設計重點從「有哪些功能」轉向「哪些互動能支撐粉絲社群關係」。

我把前期討論整理成 MVP 範圍與用戶故事，讓每個模組都能回到同一個問題：這個功能是否能讓粉絲更靠近 IP、靠近同溫層，或建立自己的追星身分？

探索 01
粉絲需要同溫層連結。
平台要讓粉絲能看見其他人也在投入，討論、留言與動態不是附加，而是社群感的地基。
探索 02
IP 回應要被放大。
被 IP 看見的瞬間有高情緒價值，因此色彩、狀態與通知都要替這件事服務。
探索 03
MVP 要能容納後續擴張。
首版不追求一次做滿，但 IA 和視覺系統必須支撐活動、探索、創作者平台與後續功能延伸。
把前期共識轉成 MVP 範圍，讓團隊先對齊「第一版要解決什麼」。
設計策略

我用取捨把新平台從舊產品慣性中拉出來，讓 MVP 保持足夠純粹。

MVP 範疇收斂時，最關鍵的取捨來自舊產品線。團隊一度討論是否延續 SHOW 展示品功能，但當新平台定位逐步清晰，我們發現它和「粉絲社群互動」的核心 IA 並不相容。

捨棄
舊產品展示品功能（SHOW）
SHOW 來自舊產品用戶行為，帶入新平台會稀釋社群定位，也增加使用者認知負擔。盤點後正式移出第一版路線圖。
保留並簡化
周邊商品入口
購買行為保留作為 IP 體驗延伸，但不自建金流與物流，改串接集團既有電商，讓設計聚焦互動到購買的情境銜接。
MVP 功能架構：把第一版要做、延後與捨棄的範疇整理成可對齊的決策依據。
介面設計

方向確定後，設計系統的任務是讓平台退居底色，讓 IP 與粉絲關係浮到前景。

以下三個設計重點，分別對應「平台如何不搶戲」、「粉絲如何理解狀態」與「系統如何支撐多模組上線」。

設計重點 01

深色底色與透明度階層，讓不同 IP 的主題內容都能成為畫面真正的主角。

平台不能搶走 IP 的品牌色與圖片記憶，所以我們選擇深色介面作為穩定容器，再用透明度建立層次，而不是維護一整套容易失控的灰階色票。

文字、底板與分隔線都從同一個白色基礎色延伸，以 95%、90%、80%、70% 等透明度區間建立層級。

這讓不同 IP 主題疊上來時，底層灰度仍然穩定；工程端也不需要維護多組靜態灰色值，實作結果更容易一致。

平台本身是底色，最精彩的永遠是 IP 與粉絲之間的故事。
設計重點 02

色彩不只是品牌裝飾，而是幫使用者辨認 IP、官方與粉絲互動三種脈絡。

hidol 介面裡同時存在 IP 發文、官方活動與粉絲留言。若全部使用同一套強調色，使用者很難快速辨認「這是誰的行為」。

粉色 · IP 發文與心動互動
紫色 · 官方活動與平台公告
五角形 · IP 身分識別

最細膩的是「翻牌留言」的色彩邏輯。IP 貼文下的留言，只有被 IP 回覆時才會出現粉色高亮；沒有被回應的留言維持灰色靜默。粉色因此有了稀缺感：出現了，就代表被看見。

設計重點 03

Icon System 以幾何語彙建立品牌記憶，同時支撐活動、探索與空狀態多種情境。

我主導系統內 icon 範疇、slot web 元件與活動、探索相關介面，讓視覺語彙不只停留在品牌規範，而是能被真實功能使用。

Spark
品牌光芒
融入象徵微光的紅點亮點，讓 icon 帶有偶像發光的情緒記憶。
Sleek
科技流線
保留線性 icon 的清爽感，用一筆畫與幾何結構呼應 hidol 的科技感。
Balanced
圓潤幾何
在方正品牌個性與社群溫度之間取得平衡，讓 icon 有辨識度也不生硬。
成果

hidol 於 2024 年 7 月上線，首版完成粉絲社群、IP 互動與創作者平台基礎。

首版上線後，後續 Moment、成就機制與 AI 粉絲應用都能在同一個架構上延伸。這也驗證了早期 IA 與視覺系統的價值：不是只完成第一版，而是替後續產品演進留下穩定地基。

專案回顧

這個專案讓我更確定，0 到 1 的設計不是把功能堆起來，而是先讓團隊看見共同的判斷標準。

hidol 的困難不只在介面複雜，而是在每個人都帶著舊產品記憶前進。設計在這裡扮演的角色，是把模糊期待整理成可討論的架構，讓取捨有依據、視覺有方向、後續模組有共同地基。這也是我在 0 到 1 專案裡最重視的能力：不是快速做出很多東西，而是讓團隊知道為什麼先做這些。
